# ADR-0015 広域データの地図表示（ベクタタイル・低ズームの簡略化・一覧のページ分割）

- 状況：California など州規模のデータで、地図が極端に重くなり PC の動作が不安定になった。州規模に複製した負荷データ
  （`scripts/stress_map_server.py`。本線 29 万・ランプ 37 万・一般道 87 万要素、施設 1,800）で再現し、z12 でのパンが
  2.3 fps（1 フレーム最大 9.8 秒）、メモリ 1.9 GB、指標の切替でタブがクラッシュした。原因は、(1) 全域の表示データを
  起動時にすべて取得・変換していた、(2) 施設名と品質警告を全施設分の HTML 要素で描いていた、(3) 表示切替・選択の
  たびに全ソース・全レイヤーを作り直し全データを描画スレッドへ送り直していた、(4) 施設一覧で全件を DOM に並べていた。
- 決定：
  1. **地図の更新**：ソース・レイヤーは 1 回だけ作り、以後は setData / setPaintProperty / setFilter / 表示切替で更新する。
     施設名は表示範囲内・上限件数（`map.label_max_count`）だけ HTML 要素で作り（オフラインのためフォントグリフを使わない）、
     品質警告は GPU で描く円の輪にする。発光の重ね描きは `map.glow_min_zoom` 以上だけ。
  2. **ベクタタイル**：道路（本線・ランプ・一般道・構造物）は `/api/tiles/{layer}/{z}/{x}/{y}.pbf`（Mapbox Vector Tile 2.1）で
     表示範囲だけ配信する。表示範囲の取得・移動後の待ち・同じ範囲のキャッシュ・ズームによる取得の打ち切り（`min_zoom`）は
     地図ライブラリの標準機能に任せる。自由な bbox での取得は、範囲が二度と一致せずキャッシュが効かないため採らなかった。
     サーバーはタイルを生成してメモリに保持し（`map.tiles.cache_tiles`）、公開 ID を付けた URL はブラウザに長期キャッシュさせる。
     施設・料金所は件数が少ないので GeoJSON のまま全件を持つ（名称の表示に使う）。
  3. **低ズームの簡略化**：本線（100 m ごと）・ランプ（約 20 m ごと）の連続する要素をまとめた版を公開時に作り
     （`display_feature.lod` 列＝まとめ数、migration 0001）、各ズームでまとめた線が数ピクセルになる版を使う
     （`map.tiles.layers.*.lod`）。色分けの値は、勾配・曲率は絶対値の最大、標高は平均、低信頼は「いずれか」、その他は最頻値。
     タイルでは線をタイル座標で簡略化し（`simplify`）、地図で使う属性だけを入れ（`props`）、数値を丸める（`round`）。
     公開時に表示データを位置の順（Z 順序曲線）に並べ、DuckDB の範囲検索で読む行を減らす。
  4. **MVT の符号化**は依存を増やさないよう最小実装を書いた（`roadmri/export/vector_tiles.py`）。テストでは別実装の
     mapbox-vector-tile（開発用の依存）で復号して確認する。
  5. **施設一覧**：1 ページ（`list.page_size`）だけ取得し、並べ替え・検索はサーバー側。CSV は同じ条件の全件をサーバーで作る。
  6. 画面表示の設定（`map`・`list`）は解析結果に影響しないので config_hash に含めない。
- 互換性：このバージョンより前に build した DB でも動く（起動時に lod 列を追加し、まとめ版がなければ元の要素で配信）。
  低ズームを軽くするには `roadmri build --range <地域> --from-step publish` で公開し直す。
- 結果：`docs/validation/map-performance.md`。
